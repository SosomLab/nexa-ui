## §1 192차 — 비트맵 컬러 이모지(CBDT·sbix PNG 글리프) — nexa-clip T-18f(DR-46) 이식

## §2 193차 — nexa-sys `LayerPresenter::trim_idle` — 유휴 때 IOSurface 풀 해제(nexa-beep 개발 세션 · mac)

- **왜**: nexa-beep이 softbuffer → IOSurface(`LayerPresenter`)로 바꾸자 present **16 → 0.9 ms**(Intel Retina · 1600×1200 · `NEXA_PAINT_TRACE`)가 됐지만,
  풀 3장(`POOL_MAX`)이 상주해 **유휴 footprint 20 → 36MB**(메인 창 948×1378×4B ≈ 5.2MB × 3). beep의 DR-5(유휴 RSS ≤30MB)를 넘는다.
  nexa-sql이 `gfx.mac_present`를 **옵트인**으로 둔 이유(+20~40MB)와 같은 벽.
- **처방**: `trim_idle(&mut self) -> usize` — `front`(레이어가 쥔 장)와 `locked`(그리는 중)만 남기고 나머지를 `drop`(CFRelease). 인덱스는 재배치.
  다음 프레임은 `pick`이 "없으면 새로(상한까지)"로 장을 만든다 — 종전 경로 그대로라 동작 불변. 호출 시점은 호스트 몫(beep = 1.5s 무프레임 · 유휴 틱 5Hz).
- **검증**: `cargo test -p nexa-sys` 7 green · clippy 0 · check-3os · beep 실측(유휴 5s vs 11s footprint — beep journal 10-10).
- 소비자 영향: 추가(새 메서드) — sql `present.rs`는 호출 0(원하면 같은 훅). [CONSUMER-CHANGES 193](../CONSUMER-CHANGES.md).

## §3 194차 — nexa-ctl `RasterCtx::caret_asked()` — 캐럿 틱 재페인트를 캐럿이 있는 창에만(nexa-beep 세션 · mac)

- **왜**: beep의 캐럿 530ms 틱은 OS 포커스 창을 무조건 다시 그렸다 → 목록 창(캐럿 없음)이 유휴에 2프레임/s(실측 `NEXA_PAINT_TRACE` 12s에 26프레임 · 10ms×2 = 유휴 CPU 2%) ·
  193차 `trim_idle`도 "1.5s 무프레임"이 안 돼 못 걸렸다(RL-9).
- **처방**: `caret_on(&self)`가 `Cell<bool>` 플래그를 세우고 `caret_asked()`로 읽는다(1 bool · 기본 동작 불변). 캐럿을 그리는 컨트롤(포커스된 TextBox · 채팅 입력줄)만 묻는다.
  호스트(beep)는 페인트 뒤 값을 창 항목에 기억해 틱 재페인트 대상을 고른다. 목록의 Connecting 회전 링은 **회전할 행이 있을 때만** 묻도록 beep 쪽에서 정정.
- 검증: check-3os ✓ · 커밋 6b2c3c2. [CONSUMER-CHANGES 194](../CONSUMER-CHANGES.md).
