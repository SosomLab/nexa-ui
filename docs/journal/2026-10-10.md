## §1 192차 — 비트맵 컬러 이모지(CBDT·sbix PNG 글리프) — nexa-clip T-18f(DR-46) 이식

- **배경**: nexa-clip이 nexa-ui로 의존을 옮기려는데(beep 10-09 docs/50과 같은 절차) clip `nclip-gfx`에만 있고 nexa-gfx에 없는 기능이 **이것 하나**였다(포크 뒤 clip이 nclip-ctl에 더한 공개 식별자 158개는 전부 nexa-ctl에 있음 · 10-10 대조). 먼저 올리지 않으면 clip이 이관 뒤 Linux 컬러 이모지를 잃는다.
- **추가**(nexa-gfx): `src/bitmap_glyph.rs`(pub(crate) · 디코드 + 캐시 128장 · PNG 512 KB·512×512 상한) · `text.rs` `draw_bitmap_glyph`(윤곽이 없는 글리프에서만 · 스트라이크 ppem → 요청 ppem 배율 · `blend_image_scaled`) · `draw_styled`의 `glyph_bitmap` None 분기에 연결. **디코더는 nexa-gfx 자체 PNG(`image::decode`)** — clip 원본의 `png` crate 의존은 가져오지 않았다(DR-3 · 외부 crate 그대로 `ab_glyph` 1개).
- **추가**(nexa-font): Linux `SYMBOL_CANDIDATES` 끝에 Noto Color Emoji 4경로(Debian/Ubuntu · Arch · Fedora · openSUSE). **반드시 마지막** — 앞의 기호 본에 있는 ✓·→는 흑백 윤곽으로 남는다. macOS Apple Color Emoji(sbix)는 미검증이라 미등재 · Windows Segoe UI Emoji는 COLR/CPAL(벡터)이라 범위 밖.
- **경계**: 시스템 글꼴 파일 안의 글리프 PNG만 푼다(clip 사용자 결정 10-05 "시스템 글꼴 한정 예외"). 진입점은 `ab_glyph::v2::GlyphImage` 하나 · 임의 바이트를 받는 공개 API 없음.
- **종류**: 추가(윤곽 있는 글리프 경로 불변 · 윤곽 없는 글리프는 종전 "빈칸" → 비트맵이 있으면 색으로).
- **시험**: nexa-gfx 37(+3 · 이모지 2건은 Linux DejaVu+Noto 있을 때만 · 없으면 건너뜀) · nexa-font 14 · nexa-ctl 440 · nexa-dlg 6 · workspace check 0 · check-3os ✓(win).
- **영향**: clip = 이관 뒤 Linux 이모지 유지(이관 커밋에서 실기) · beep·sql·dir3 = 영향 없음(폴백 체인에 Noto Color Emoji가 들어가면 Linux에서 이모지가 색으로 — `check`).
