## §2. 248차 — nexa-sys `LayerPresenter` 프레임 나이 `Frame::age()`(nexa-dir3 10-31 macOS 부분 그리기)

- **왜**: nexa-dir3 협업 계측(10-31 dir3 journal §15) — macOS 유휴 프레임이 전부 `mode=full`. softbuffer 0.4 CG 뒷단의 `age()`가 늘 0이라 dir3 `frame_plan`이 부분 그리기를 한 번도 고르지 못했다. dir3가 `gfx.mac_present` 기본을 iosurface로 바꾼 뒤(dir3 74c5da6) `LayerPresenter`에도 나이 정보가 없으면 같은 문제가 남는다.
- **무엇(af368ff)**: `Frame::age()` 추가(softbuffer `Buffer::age`와 같은 뜻 · 0 = 내용 모름 · 1 = 바로 지난 프레임 · n = n프레임 전).
  - 직접 경로는 `Surf.seq`(그 표면을 마지막으로 낸 프레임 번호)와 `LayerPresenter.seq`(낸 프레임 수)로 계산한다. 순수 함수 `surface_age(now, surf)` = `now + 1 − surf`이고, 새 표면이나 미래 번호는 0, 상한은 255다.
  - 중간 버퍼 경로(행 간격 ≠ 폭 × 4)는 `staging_age(now)`다. 모든 프레임이 같은 staging 버퍼를 거치고 `present_locked`가 통째 복사하므로, 한 번이라도 냈으면 1이다.
  - 크기가 바뀌면 `seq`를 0으로 돌린다. 공개 API는 추가만 했고, 호출하지 않으면 동작은 그대로다.
- **검증**: 시험 `surface_age_counts_frames_since_last_present`(새 표면 · 바로 지난 프레임 · 삼중 회전 3 · 미래 번호 · 상한 · staging) · `cargo test -p nexa-sys` 10/0(협업 재실행 · mac · 별도 target-dir) · nexa-sql `cargo check` ✓(개발 · 별도 target-dir) · 커밋 **af368ff**(feat) · **f2420b4**(CONSUMER-CHANGES 248 행).
- **소비자**:
  - nexa-sql: 영향 없음(호출하지 않음). 원하면 nexa-sql present.rs도 `age`로 부분 그리기를 할 수 있다.
  - nexa-dir3: 소비처다. `present.rs` `Buffer::Layer(f) => f.age()` → `paint::frame_plan`이 age n이면 이번 사각형과 지난 n−1 프레임 사각형의 합집합을 그린다. 이력 상한은 8이고, 넘으면 Full이다. Full 프레임도 창 전체 사각형으로 이력에 넣고, 크기가 바뀌면 이력을 비운다. 시험은 `frame_plan_age_n_unions_recent_history`이고, 실측 수치는 dir3 journal에 적는다.

## §3. 249차 — nexa-ctl `SearchBox::tooltip_visible()` · `toggle_rect(which)`(nexa-dir3 10-31 macOS 툴팁 깜빡임)

- **왜**: 사용자 보고(10-31 · 맥)에서 검색창 토글 툴팁이 안 보이거나, 보일 때도 깜빡였다. 원인은 두 가지다.
  - ⓐ dir3 `panel.rs`가 버튼을 누르지 않은 `MouseMove`를 검색창에 넘기지 않아 호버 툴팁이 뜰 수 없었다(dir3 쪽 결함).
  - ⓑ 토글 툴팁은 상자 틀 밖에 그리는 팝업이다. 그런데 호스트가 표시 여부를 알 길이 없었다(종전 공개 판정 = `popup_open()` 편집 메뉴뿐). 그래서 dir3 macOS 부분 다시 그리기(IOSurface age 3 · dir3 71add88)에서 툴팁이 부분 프레임의 클립에 잘려 표면마다 다르게 그려졌다. Windows · X11은 age 1이라 드러나지 않았다.
- **무엇(2ffbbbc)**: `SearchBox::tooltip_visible()`(토글 툴팁이 지금 보이는가)과 `toggle_rect(which)`(토글 자리 · 시험·호스트용)를 추가했다. 새 메서드만 있어 동작은 그대로다.
- **검증**: 시험 1(머묾 + 지연 0 틱 → 보임 · 벗어남 → 사라짐 · 범위 토글 기본 없음) · nexa-sql `cargo check` ✓(개발 · 별도 target-dir) · 커밋 **2ffbbbc**(feat) · **482d7ae**(CONSUMER-CHANGES 249 행).
- **소비자**:
  - nexa-sql: 영향 없음(추가 API만). 검색 상자 툴팁을 쓰는 창이 부분 그리기를 하게 되면 같은 판정에 넣어야 한다.
  - nexa-dir3: 소비처다. dad9369에서 `Panel::popups_open`에 검색창 편집 메뉴와 토글 툴팁을 넣었다(→ 오버레이 = 전체 프레임). 누르지 않은 `MouseMove`도 검색창에 넘긴다. 시험은 `filter_toggle_tooltip_counts_as_overlay`다.
